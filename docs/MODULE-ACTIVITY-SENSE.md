## 0. 一句话

在邻伴三端新增「健康活动感知」板块：以老人家庭 Wi-Fi 信号回传（APP 侧连接心跳 + 可选 Wi-Fi 网关信号特征）**无感**推断老人的活动与健康状态，转化为三重价值——

1. **引流入口**：装机/授权即家庭入口，感知数据积累后由子女侧看到「父母最近活动变少了」；
2. **转化引擎**：活动状态驱动派单加权与主动推荐，把感知信号变成陪聊订单；
3. **安全兜底**：久静/离线超阈自动干预（客服外呼 → 必要时紧急联系人/社区），把风险转成订单。

**本模块不是独立产品，是邻伴的「感知层 + 增长层」**：主业仍是陪聊，感知数据服务于下单、派单、复购与安全。

## 1. 来源与差异化

**来源页面**：https://duckwolf.cn/wifi.html《智能家庭守护者》——用家中 Wi-Fi 信号遇人体反射后的路径与强度微变，做无接触健康与安全监测：室内活动热力图、跌倒预警、长时间静止预警、夜间异常活动、无创呼吸趋势；**不用摄像头、不用麦克风**，隐私是其核心卖点；商业档位为免费 / 高级 ¥49 月 / 机构定制。

**在邻伴里的位置**：duckwolf 是「感知技术方案」，邻伴是「服务交易平台」。本模块把前者作为**数据源**接入后者——

| 维度 | duckwolf.cn | 邻伴本模块 |
|---|---|---|
| 形态 | 独立产品页（To C 订阅） | 邻伴三端内的板块（To C + To B） |
| 收入 | 订阅 ¥49/月 | 免费层作引流钩子；高级层与机构层另计；**订阅收入不占陪聊分账池** |
| 关系 | 感知方案来源 | 服务主业（陪聊）承接转化 |

**护城河叠加**：亲邻社区媒体（门禁/单元门/开门 App）提供线下信任锚，Wi-Fi 感知提供「活动状态」数据锚，两者叠加让「谁在陪、陪得怎么样、老人状态如何」形成闭环数据资产。

## 2. 与三端的咬合（板块落位）

| 端 | 新增板块 | 作用 |
|---|---|---|
| **用户端（老人）** | 我的 → 健康守护：① 活动日报（今日活跃时段 / 出门次数 / 久静提示）② 设备管理（已装网关 / 绑定 Wi-Fi / 探针状态）③ 隐私中心（谁在看我、授权开关、一键停采） | 装机即入口；老人可见 = 反监视设计，安心前提 |
| **用户端（子女代下单）** | 父母健康看板：日/周活跃趋势、久静与异常告警、**「为父母预约陪聊」一键转化** | **付费转化主场景**（子女付费） |
| **陪聊员端** | 派单推荐排序加权（老人活跃度低/久静优先派单）；服务中提示「今日老人活动量偏低，可多陪伴」 | 订单转化 + 服务质量 |
| **管理端** | ① 健康活动看板：活跃时段分布 / 设备在线率 / 告警处理工单 ② **引流漏斗**：装机→激活→数据可用→告警→首单→复购 ③ 订阅收入（¥49/月，与陪聊分账**分账口径分离**） | 运营与商业化 |

## 3. 数据通道（双通道 + 统一模型）

### 通道 A：APP 侧 Wi-Fi 状态心跳（零硬件，MVP 必做）
**采集信号**：Wi-Fi 连接状态、SSID/BSSID 的 HMAC 哈希、网络切换事件、前后台驻留时长、可选步数与加速度计活动计数。
**推断能力**：在家/外出、日活动量、作息规律（作息点识别）、夜间异常活跃、与订单/IM 的交叉验证。

### 通道 B：Wi-Fi 网关信号特征（硬件，W+1）
按 duckwolf 方案接入网关：**原始波形/CSI 不出户**，特征提取在网关本地完成，仅上报特征向量 + 事件（房间级活动强度、跌倒疑似、呼吸趋势估计）。
**硬件与算法当前为规划态**（duckwolf 商业计划书第一阶段），本模块只做**协议与接入位预留**，不阻塞 MVP。

### 统一模型（所有通道归一）
```
activity_signals（时间窗 + 特征 + 置信度 + 来源通道）
   → activity_daily_summary（日聚合：活跃时段分布、活动量、久静次数、居家时长）
   → health_alerts（久静 / 跌倒疑似 / 夜间异常 / 设备离线超阈）
```
**活动状态分级**（必须带**置信度**与**数据新鲜度**，禁止"假装确定"）：
`ACTIVE`（活跃） / `LOW`（低活跃） / `STILL`（久静） / `AWAY`（外出或离线） / `UNKNOWN`（数据不足）。

## 4. 引流引擎（客户明确的「用于引流」）

**漏斗**：装机/授权 → 家庭账号绑定 → 感知数据积累（3–7 天）→ 子女看到「父母活跃下降」→ 推送/落地页推荐陪聊 → 下单 → 复购。

**三条引流触发器**
1. **活跃下降触发**：连续 3 日活动量下降 > 30% → 子女端文案「最近爸妈活动变少了，有人陪着聊聊天更安心」+ 陪聊推荐位；
2. **久静触发**：连续静默超阈值 → 安全提示 + 推荐「上门探访型」陪聊（可用时长卡引流）；
3. **新装体验触发**：前 7 天免费体验期 → AI 陪聊 + 首次陪聊优惠券（把装机用户导向平台已建成的 AI 陪聊与陪聊员供给）。

**归因指标**：装机→激活率、感知数据可用率、告警→下单转化率、告警→复购率、单均带新成本（对比亲邻社区媒体投放口径）。

## 5. 商业化口径

| 层 | 内容 | 定价 | 与陪聊主业关系 |
|---|---|---|---|
| 免费层 | 基础活动日报 + 在家/外出判断 | ¥0 | **引流钩子**：装机即得，感知数据换订单 |
| 高级层 | AI 健康分析、跌倒/久静预警、历史回溯、多成员管理 | ¥49/月（对齐 duckwolf 档位） | 增值收入 |
| 机构层 | 多房间集中监测（街道/养老机构/保险公司） | 定制 | B 端批量获客与政府/保险支付方 |

**账务隔离（硬要求）**：订阅收入进平台营收科目，**不进陪聊分账池**；管理端分账页必须区分「陪聊分账」与「订阅收入」两个口径，避免污染抽成与对账模型（DATABASE.md §5 资金表设计已锁定陪聊分账语义，此项需新增独立科目）。

## 6. 隐私与合规红线（不可协商）

1. **无摄像头、无麦克风**、子女端默认**不做实时轨迹回放**（仅聚合趋势；实时回放属专业版且需老人单独授权）；
2. **SSID / BSSID / MAC 一律不落原文**：只上报 HMAC 哈希（BSSID 哈希仅用于识别「是否同一个家」）；
3. **原始信号特征不出户**：通道 B 的原始波形与 CSI 只在网关本地处理，仅上传特征；
4. **双层知情同意**：老人本人授权 + 子女可见范围由老人侧可调（老人能在隐私中心看到「谁在看我」并随时收回）；
5. **健康推断仅作趋势参考**，不作诊断、不作医疗结论（无创呼吸率等必须标注「参考指标，非医疗诊断」）；
6. **留存策略**：原始特征短周期留存（≤14 天）自动清理，只保留日聚合与事件；
7. **一键关闭**：老人可随时关闭感知与共享，关闭后立即停止采集并删除未聚合数据；
8. **人工兜底链路**：独居老人异常先客服外呼 → 必要时联系紧急联系人/社区，与现有 SOS 链路共用出口。

| 阶段 | 内容 | 依赖 |
|---|---|---|

## 8. 风险与红线

| 风险 | 表现 | 缓释 |
|---|---|---|
| **误判** | 久静 = 老人出门了，而非身体不适 | **必须双通道交叉验证**（Wi-Fi 活动 + 订单/IM/步数/门禁触点），单通道不得直接下「不健康」结论 |
| 告警疲劳 | 误报频出 → 子女屏蔽通知 → 触达失效 | 告警分级（提醒/预警/紧急）+ 人工确认后才升级 + 抑制窗口 |
| 隐私舆情 | 「装个路由器就被监视」 | 隐私中心可见 + 无摄像头声明 + 老人可一键关 + 数据不出户 |
| 合规越界 | 无创健康数据被当医疗结论 | 文案与接口强制「参考指标」标注，禁止诊断类表述 |
| 商业合规 | 涉「健康数据」特殊类别信息 | 单独同意 + 最小化采集 + 留存期限 + 可审计（audit_logs） |
