# 邻伴 · 社区养老陪伴匹配平台

![CI](https://github.com/tomwugdgz/linban-app-/actions/workflows/ci.yml/badge.svg)
![License](https://img.shields.io/badge/license-MIT-blue.svg)

> **让每一位老人都能被看见、被陪伴** —— 基于亲邻社区媒体与 AI 匹配引擎，连接「共享儿子·时间银行·社区志愿者·专业陪护」四位一体的同城陪伴 O2O 平台。

## 🧭 战略定位

### 一句话定位

以**亲邻社区媒体**（门禁灯箱 + 单元门灯箱 + 开门 App）为信任与流量底座，在广州单城试点**四位一体**陪伴匹配平台，先切**就医陪诊与情感陪伴**两类刚需，用「保险/长护险 + 子女代付 + 街道政府采购买单」组合变现，跑通最小闭环后向全国复制。

### 竞争格局

| 模式 | 代表 | 机制 | 付费 | 核心局限 |
|---|---|---|---|---|
| 时间银行 | 南京时间银行、上海「沪助时光汇」 | 低龄帮高龄，存时光币 | 免费互助 | 跨区兑换难，年轻人少 |
| 陪诊平台 | 国融乐养、蓝豚医陪、向阳陪诊团 | 持证陪诊师 1 对 1 | 付费/公益 | 获客成本高，信任建立慢 |
| 共享儿女 | 自媒体议题 | 概念阶段 | — | 未成规模平台 |
| **邻伴** | 亲邻资源 + 四位一体 + AI 匹配 | 匹配引擎 + 社区媒体信任锚 | 多元支付 | 待广州 MVP 验证 |

### 中美差异与本土化策略

| 维度 | 美国（Papa 土壤） | 中国（邻伴土壤） | 本土化应对 |
|---|---|---|---|
| 文化 | 个人主义，接受外部陪伴 | 孝道，「花钱找人陪 = 不孝」 | 话术「**辅助子女**」而非「替代子女」 |
| 付费意愿 | 非医疗陪伴愿付费 | 非医疗陪伴付费意愿低 | 主切**陪诊/代跑腿/教手机**高意愿场景 |
| 支付方 | 商保/Medicare 覆盖 | 社保为主，长护险 49 城试点 | 长护险 + 街道采购 + 子女代付 |
| 信任基础 | 平台筛选 + 评价 | 熟人社区信任更强 | 亲邻门禁媒体 + 开门 App 实名锚 |

### 变现结构

| 收入流 | 支付方 | 可行性 | 备注 |
|---|---|---|---|
| 保险/长护险合作 | 商保、长护险试点 | 中（需效果数据） | 对标 Papa 保险闭环 |

## 👥 四位一体供给模型

邻伴的供给侧不是单一角色，而是**四种供给身份并行**，各有不同的结算路径与信任机制：

| 角色 | 人群 | 服务内容 | 结算方式 | 信任机制 |
|---|---|---|---|---|
| **共享儿子** 🔥 | 大学生/年轻职场 | 陪聊、教手机、陪逛、代跑腿 | **时薪付费（进分账）** | 实名 + 培训 + 双向评价 |
| **时间银行** ⏳ | 低龄健康老人 | 陪聊、简单家务、陪诊 | 积分兑换（预留） | 社区熟人背书 |
| **社区志愿者** 🏘️ | 在地热心居民 | 定期探访、节日陪伴 | 荣誉 + 补贴（预留） | 街道/居委会认证 |
| **专业陪护** 🏥 | 持证陪诊师/护理员 | 就医陪诊、康复辅助、健康监测 | **高客单付费（进分账）** | 资格证 + 保险 + 平台担保 |

> **工程纪律**：供给角色（`companion_role`）、服务类型（`service_type`）、能力标签（`tags`）三者**正交**。
> 「一位陪聊员是什么角色」「提供什么服务」「会什么方言棋牌」是三个独立维度。
> 本轮仅开放**共享儿子**与**专业陪护**（进分账）；时间银行与社区志愿者仅预留枚举，**绝不进分账流水**。

### 话术红线

| ✅ 正确口径 | ❌ 禁止用语 |
|---|---|
| 辅助子女（帮子女尽一份心） | 替代子女 / 像儿子一样伺候 |
| 陪聊、教手机、陪逛、代跑腿 | 护理 / 照护 / 喂食 / 洗澡 |
| 社区里的年轻后辈 | 护工 / 保姆 / 孝子贤孙 |
| 按时陪伴、按小时计酬 | 专业护理 / 医疗陪护 |

## 🛡️ 亲邻社区媒体护城河

邻伴的最大差异化优势：**亲邻社区媒体是获客与信任的既有基础设施**，单位获客成本与信任建立成本显著低于纯线上陪诊平台。

| 资产 | 规模 | 在邻伴用途 |
|---|---|---|
| **开门 App** | 实名 3,000 万+，月活 2,000 万+，单月人脸开门过亿次 | 流量入口 + 实名信任 + 双侧触达 |
| **单元门灯箱** | 330×558mm 静态灯箱 + 语音播报，日均到达率 87% | 线下获客 + 品牌信任锚 + 志愿者招募 |
| **广告门** | 全国 70,000+ 小区，覆盖 3 亿城镇家庭（77% 门禁市场） | 规模化复制时的低成本曝光网络 |
| **5V 社区数据** | 67,651 点位 / 220 城市 | 精准匹配与选点 |

> **护城河逻辑**：Papa 在美国最大成本是获客与信任建立；亲邻用「门禁物理触点 + 实名 App」把这两件事变成**既有基础设施**，使单位获客成本与信任建立成本显著低于纯线上陪诊平台。

## 🚀 快速开始

### 前置要求

- Node.js >= 20
- npm >= 10
- Docker & Docker Compose（本地开发可选）
- MySQL 8.0

### 安装依赖

```bash
npm install
```

### 本地启动

#### 方式一：Docker Compose（推荐）

```bash
docker-compose up -d
```

这将启动 MySQL + Redis 容器并自动执行初始化脚本。

#### 方式二：手动启动

1. **配置环境变量**

   在 `apps/server/.env` 中设置：
   ```env
   DATABASE_URL="mysql://user:password@localhost:3306/linban"
   REDIS_URL="redis://localhost:6379"
   JWT_SECRET="your-secret-key"
   ```

2. **数据库迁移**
   ```bash
   cd apps/server
   npx prisma migrate deploy
   npx prisma generate
   ```

3. **启动各服务**
   ```bash
   # 后端
   npm run dev --workspace @linban/server

   # 管理后台
   npm run dev --workspace @linban/admin-web

   # 小程序（H5 预览）
   npm run dev:h5 --workspace @linban/miniapp-user
   ```

## ✅ 门禁系统

本项目实施 **16 项聚合门禁**，确保代码质量与数据一致性。

### 运行门禁

```bash
npm run verify:all      # 全量门禁
npm run verify:list     # 列出所有门禁项
npm run verify:all -- --only=typecheck,test,collect  # 只跑特定分组
```

### 退出码分级

| 退出码 | 含义 |
|---|---|
| 0 | 全部通过 |
| 1 | 存在真失败（断言失败） |
| 2 | 疑似收集阶段失败 |
| 3 | 有跳过项且 `--strict` 模式 |

### 门禁纪律

- **收集完整性必须是第一步** —— 防止守门测试被静默丢弃
- **不依赖 DB 就能跑通必需门禁** —— PR 门禁可在无数据库环境执行
- **三态区分**：「还没写」（WARN）≠「写了没跑」（ERROR）≠「正常」（PASS）

## 🗺️ 广州单城试点路线

| 阶段 | 主题 | 关键指标 |
|---|---|---|
| **0–3 月** | 冷启动 | 跑通 50 单陪诊；动员低龄老人建时间银行；招募首批持证陪诊师 |

- **选点**：越秀/海珠老城区（高龄独居密集）做冷启动；珠江新城高端社区（子女付费能力强）做付费验证
- **北极星指标**：月均成功匹配单量
- **安全红线**：安全事件数 **须为 0**
